# Working on starprint

Context for anyone (human or agent) changing this crate. The README is
for users; this file is for contributors.

## Layout

- `src/document.rs` — `Builder<P>` and the command encoding. `StarLine`
  (thermal, Star Line Mode) and `Impact` (SP700, Star Mode) are sealed
  markers; protocol-specific commands live in the `impl Builder<…>`
  blocks. Every command cites the manual it comes from.
- `src/graphics.rs` (+ `graphics/dither.rs`, `graphics/pipeline.rs`) —
  bitmaps, dithering, and the `image`-feature pipeline.
- `src/transport.rs` — `Transport` trait and `TcpTransport` (port 9100).
- `manuals/` — the Star command specifications and hardware manuals the
  code is written against. Check bytes there, not from memory.
- `tests/fixtures/` — golden output generated by the reference Python
  implementation in the sibling `starprint` repo (`generate.py`). The
  impact pipeline, dithering and `ESC ^` serialisation must stay
  byte-identical to it.

## Conventions

- Run `cargo test --all-targets` and `cargo test --features image`, plus
  clippy with `-D warnings` and `cargo fmt --check`, in both feature
  configurations before committing. CI does the same.
- Public names follow the Rust API guidelines: nouns for types, verbs for
  methods, module names are domain nouns; anything the `Builder` accepts
  lives at the crate root.
- Docs and commit messages use British English. Commits are subject-only,
  imperative, at most 72 characters.

## Hardware facts learnt on real printers

Test printers: a Star TSP800II (thermal, 80 mm paper via a spacer, print
width set to 80 mm) and a Star SP700 (impact).

- **Ethernet cards drop data.** The IFBD-HE07/08 cards do not apply TCP
  back-pressure; fed a large job at once they silently discard it, and
  they also discard a job sent while the printer is still busy. Hence
  `TcpTransport` paces writes (1400 bytes every 20 ms, ~70 KB/s, the rate
  that never lost a job) and callers must send one job at a time. Status
  back (ASB) is the proper fix and is not implemented yet.
- **Raster image buffer.** The TSP800II expands raster rows into a buffer
  of roughly 2,560 rows and prints it when full before taking more data;
  the pause leaves a faint line across a long image. At normal resolution
  that is ~320 mm of paper, in double-resolution mode ~160 mm.
- **Thermal photo settings that printed best:** normal resolution, slow
  speed (`print_speed(PrintSpeed::Slow)`), density +3
  (`print_density(3)`), `RasterQuality::High`, with the thermal tone
  curve (`ToneCurve::THERMAL`, gamma 0.55, no equalisation). Double
  resolution (`PrintMode::DoubleResolution` plus a
  `*_DOUBLE_RESOLUTION` profile) is smoother on short images but subject
  to the buffer limit above.
- **Tone curves differ by head.** The impact curve (gamma 1.8 +
  equalise) is the hardware-tuned reference and must not change; on a
  thermal head it crushes shadows completely, which is why `HeadKind`
  selects the curve.
- **Cheap thermal paper** pinholes in solid black at default speed and
  density; slow speed and +2/+3 density cure it.
- **Narrow paper on the TSP800II.** Set the print width memory switch to
  80 mm before printing on 80 mm rolls, otherwise the head fires onto
  bare platen. Star warns that long narrow use wears the exposed strip of
  head; at hobby volumes it is irrelevant.
- **Double-resolution mode is vertical:** 16 rows/mm at the same 8
  dots/mm horizontally; images need twice the rows (the profiles handle
  it). The mode outlives `ESC @`, so switch back explicitly.

## Diagnostics

- `cargo run --example thermal_test_pattern -- <host> 80 slow density=3`
  prints a head-check page: a solid bar (white hairline = dead element),
  hairlines, checkerboard, grey ramp, fonts and codes.
- `cargo run --example thermal_image --features image -- <host> photo.jpg
  slow density=3 [double] [rotate] [gamma=F] [equalize=0|1]` for photos;
  `rotate` runs a landscape picture along the paper.
- `cargo run --example impact_image --features image -- <host> photo.jpg
  double [rotate]` for the SP700.
